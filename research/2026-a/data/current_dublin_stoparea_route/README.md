# Dublin official stop-area route: access gate

The National Transport Authority (NTA) catalogue identifies a national GTFS schedule feed, but its two linked schedule ZIP downloads returned HTTP 403 in this environment on 10 November 2026 UTC. No stop records or hierarchy were obtained, so this route supplies **no new city stop count**. The failure is specific to these requests and does not establish that the publisher's data is unavailable to other users.

The [NTA GTFS catalogue](https://data.gov.ie/api/3/action/package_show?id=nta-gtfs) names `GTFS_All.zip` and `GTFS_Realtime.zip` (the latter described as GTFS for realtime operators); the catalogue distinguishes the separate real-time API, which requires an API key. The [NTA developer page](https://developer.nationaltransport.ie/GTFS) says its contents change with public-transport schedules. Neither catalogue identifies whether current `stops.txt` contains populated `location_type=1` and `parent_station` fields, nor proves the extent of native grouping. The Irish [NeTEx stop examples](https://netex.ie/examplesStop.htm) describe NaPTAN StopArea-to-StopPlace and StopPoint-to-Quay mappings; they are illustrative schema examples, not a current network inventory. The profile also describes creating a StopPlace where a StopArea is absent; this investigation does not independently infer such groups from names or proximity.

The previously investigated NaPTAN Stop Areas/Stop Points links and their 403 responses are recorded in [`../task4_v121_transport/README.md`](../task4_v121_transport/README.md); they were not repeated here. The existing 19-stop city-centre tram subset is a historical inventory proxy, not a current total. This route does not alter that evidence, the original CSV, model or manuscript.

## Reopening conditions

Obtain an authorized publisher GTFS or populated NeTEx/NaPTAN release, retaining its original bytes and publication/retrieval dates. Verify actual native parent relationships and their completeness, operator and mode coverage, public passenger eligibility, and calendar/calendar_dates service dates for the chosen analysis period. Define and obtain the compatible Dublin city boundary, coordinate reference system, treatment of border-crossing groups and population denominator before spatial selection. Reconcile groups across modes using publisher-provided identifiers and document any ungrouped eligible stops; neither count poles as stop areas nor group by an arbitrary distance or name. Check overlap with the existing tram subset before any combination. A schema description or schedule feed alone is not a verified city inventory.

## Reproduction and receipts

`manifest.json` records request URLs, UTC times, response status and SHA-256 of each complete saved body. Both 403 bodies are 13-byte responses, not feeds. `acquire.py` records fresh network responses with a 5 MB cap; rerunning it replaces these snapshot receipts, so preserve this directory first if acquiring a new snapshot. The NeTEx PDF exceeded that cap and its partial response was discarded; no conclusions depend on that discarded response. The smaller examples page is retained. No large feeds were downloaded.

Run `python research/2026-a/data/current_dublin_stoparea_route/extract.py` from the repository root to verify recorded body lengths and hashes, extract the catalogue links and statuses, and regenerate `extract.json`. The extractor checks the presence of mapping terms; it does not validate the semantics or completeness of a live stop hierarchy.
