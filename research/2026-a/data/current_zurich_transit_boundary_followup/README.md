# Zurich 站点：把名称筛选推进到市界和原生标识核验

本轮解决了旧479条候选的部分地理与身份问题：官方市镇261（Zürich）多边形与原站点公布坐标叠加后，478条落在市界内，其中460条列有线路；3条记录的`cname`属性与几何归属不一致。国家当前服务点的同市镇查询完整取得579条公布记录，旧市界内478条中474条可按完整DiDok编号字符串精确对应。它们都是记录级核查结果，尚未建立与原VBZ 446站相同计数单位的商业／物理站区去重规则，因此主数据准入和实际区间收窄均为0，446及原人口保持。

## 原件与空间口径

- 旧站点原件复用`../current_zurich_transport/kanton_zh_wfs.geojson`，3004条，EPSG2056；它标注数据日期14.12.2025，不重新下载成“新观测”。
- 新[站点元数据](https://geolion.zh.ch/geodatensatz/883)明确`nhstid`的VBZ本地号、区域号及DiDok号三类之间可能冗余，并说明铁路站与相邻公交站分别记录。因此，四个字段在旧479条中各自唯一，也不能证明物理站唯一；`diva_nr`没有在该说明中获得可用于商业站合并的定义。
- 新[市镇边界元数据](https://geolion.zh.ch/geodatensatz/865)的数据标签为30.01.2026，元数据更新日01.09.2026。[边界WFS服务说明](https://geolion.zh.ch/geodatenservice/1054)区分正式市镇边界与挖去湖面的变体。本包使用`ms:gem_grenzen`、BFS字段等于261的唯一正式市镇多边形，而非Greater City的22市镇范围或按城市名称推断的边界。返回的市镇名、代码、CRS及几何有效性均核验。

按公布坐标，`Uetliberg, Bahnhof`（8511418，cname为Ringlikon）在市界内；`Zürich, Fernsehstudio`（8591128）和`Zürich, Orionstrasse`（8591297）在市界外。三个点距边界约17.15、24.21、44.39米。本包保留全部3004条点的分类和距离；这些是确定输入坐标的几何计算，不将元数据的标称位置精度当成严格误差包络，也不倒推2025边界未变化。

## 国家名录与身份对应

国家FOT接口的`stop-points-today`先用同市镇条件发现总数579，再按`number`排序、offset0至500共六页取回，分别100/100/100/100/100/79条。每页公布总数均为579；合并后编号唯一、次序一致、`fsonumber=261`，每个公布点也落在所选多边形内。六页在约1.4秒内取得，但没有跨请求事务或不可变国家版本标识；这是已归档的当前市镇查询，不是全国完整名单或2025普查。URL、UTC、状态、类型、长度和SHA见`retrievals.json`。

579条中`ORDERLY`为473、`ON_REQUEST`为5、类型为空为101。类型为空不自动解释为无用或不存在；整份目录可能含运营／货运等角色。供应方将此FOT列表定位为手工查询，说明它不适合定期自动采集；本包是一次有限研究归档，后续机器采集应改用其建议的主数据集或Atlas接口，不定时轮询这个端点。国家文档对`parent`与商业站的反例及字段含义见`results/current_swiss_servicepoint_followup/`。即使是`ORDERLY`或有线路的记录，也不单独证明特定日期已实际运行、所有学生可使用，或不同编号对应不同商业站区。

旧市界内478条中，474条只按完整`nhstid == number`匹配，没有转换短号、解析前缀、使用`diva_nr`、模糊名称或距离聚类。对应表同时保留两期名称、服务类型和坐标差。4条没有出现在这次市镇查询中：8503044、8503449、8516661、8585407；这不证明它们在全国名录中缺席或已经停运，也不证明编号历史实体与设施位置完全不变。精确标识对应不能替代商业站区合并或时点匹配。
