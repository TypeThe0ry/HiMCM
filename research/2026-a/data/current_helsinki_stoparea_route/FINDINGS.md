# HSL native area route: bounded feasibility check

The HSL GTFS feed supplies explicit `area_id` memberships, providing a promising native grouping route without name or distance matching. The observed snapshot has 4,715 distinct area IDs and maps 8,266 distinct stop IDs to an area; no stop appears in multiple areas and all referenced IDs resolve. Of 2,636 stop records with an H-prefixed public code, all are mapped. These are feed-wide integrity diagnostics, not a Helsinki stop-area count or a model input. HSL says H prefixes denote Helsinki stops, but the code is not a city boundary. One area combines an H-prefixed stop and at least one other stop (including potentially an empty code); spatial boundary policy is unresolved.

The [GTFS specification](https://gtfs.org/documentation/schedule/reference/#areastxt) defines `areas.txt` and `stop_areas.txt` as area groupings and stop membership, including use in fares; it does **not** establish that these IDs equal physical stop places or Oslo's StopPlace unit. HSL-specific authoritative semantics and cross-city comparability remain to be verified before adoption. The alternative `parent_station` field is populated for 437 of 8,387 total stop records, so relying on it alone would omit many records. Example area `110007` assigns both `1010107` and `1010108`; this is a provider assignment, not a name-based merge.

The [HSL source](https://www.hsl.fi/hsl/avoin-data) says its GTFS is built daily from the transport register for routes with valid schedules, covering two months from the start of the extraction week. `feed_info.txt` reports 2026-11-09 through 2027-01-07, feed version `2026-11-10 05:38:26`. This is the schedule feed's horizon, not proof that every included stop has service on any particular date or of observed operation. A date-specific mode filter requires joining `calendar.txt` and `calendar_dates.txt` to `trips.txt`, `routes.txt`, and `stop_times.txt`, resolving exceptions, then area membership. The latter member is 75,568,467 compressed bytes and 1,117,196,069 expanded bytes and was not extracted in this bounded check. Route type 3 would select GTFS bus trips, subject to confirming the intended mode scope. No service-day filter was performed.

The [City of Helsinki district division](https://hri.fi/data/en_GB/dataset/helsingin-piirijako) offers a possible official boundary source. No geometry was retrieved or applied in this investigation. A future analysis must select and document its dated boundary, CRS, point-in-polygon rule, handling of area members across the boundary, service date, and area geometry rule; it must not silently equate a code prefix or member mean to a municipality polygon.

## Reproducibility and provenance

`acquire.py` fetched ZIP byte ranges rather than downloading the 87,852,429-byte archive. It saves response bodies, request and response headers, UTC retrieval times, status codes and SHA-256 hashes in `http_manifest.json`. Range requests use `If-Match` with the HEAD ETag and check 206, matching ETag and response length; the manifest also records `Content-Range` and Last-Modified. ZIP CRC is checked on extracted members by Python. Response metadata is restricted to an explicit ETag, Last-Modified, Content-Range, Content-Length, Content-Type and Date allowlist. The archive ETag was `0x8DF3EDD9ABACD39`; the archive URL is [HSL GTFS](https://infopalvelut.storage.hsldev.com/gtfs/hsl.zip). The original HTTP response bodies are the `range_*.bin` files; extracted text is derived. `python extract.py` runs offline against the saved matching range bodies, verifies their hashes, status, ETag, Content-Range and lengths, and lets Python verify each ZIP CRC. `python extract.py --trips` additionally extracts the saved compressed trips member to `/data/scratch/himcm_hsl_gtfs_trips.txt` (39.5 MB expanded); it is not needed for the inventory summary. `python summarize.py` reproduces `inventory_summary.json`. No full ZIP checksum is claimed.

Direct requests for HSL's open-data page returned HTTP 403; the saved HTML is the error body, not the source text. The primary HSL page and GTFS reference were independently read through web retrieval. HSL specifies CC BY 4.0 with provider and release time attribution for its listed data; verify the source terms before redistribution. This check did not change the original CSV, manuscript, model, or registries.
