# Entur stop-place semantics: implications for Oslo

**The official material supports native parent grouping, but does not establish that every resulting group corresponds to one deduplicated physical facility.** The 829 parent-collapsed mode-bearing roots remain an administrative alternative count, not an admitted replacement for the 89-station physical subset. In particular, the material does not establish that separate Trosterud or Midtstuen roots should be merged, and gives no general 250 m physical-diameter rule.

Entur's [two-quay example](https://github.com/entur/profile-examples/blob/master/netex/stops/BasicStopPlace-two-quays_example.xml) explicitly represents one stop place containing two directional roadside quays. This supports not counting quays as independent stops. Its [Oslo S example](https://github.com/entur/profile-examples/blob/master/netex/stops/OsloS_station_example.xml) shows separate bus and tram monomodal StopPlaces referring to one multimodal parent via `ParentSiteRef`. The file explicitly says it is a general example, not the Norwegian NeTEx profile, and part uses old dummy values; it illustrates representation rather than establishing a complete current grouping rule for Oslo.

The official [Tiamat backend documentation](https://github.com/entur/tiamat) describes matching and merge options, including matching imported stops by name and coordinates; it does not establish that all real-world co-located stops have been grouped. Its `versionValidity=CURRENT` selects record versions valid at the present time. Version validity alone is not evidence that a passenger service currently calls at each record. Entur's existing archived [NSR introduction](../current_oslo_transport/semantics_nsr.html) states that all stops in active public-transport use are required to be represented and active, but that requirement does not establish the converse for each exported record or prove perfect completeness in a snapshot.

The three original upstream files are captured byte-for-byte here. `provenance.json` records URL, UTC, HTTP status and SHA-256. The earlier N801 endpoint failure is recorded in the existing source audit; it was not retried. No source here authorizes adding 829 to 89, deduplicating roots by distance, or changing the primary model.
