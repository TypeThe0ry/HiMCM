# Prague PID stop-list reuse: mode gate unresolved

The archived 2026-11-09 PID Prague-only stop-list responses provide a reproducible **all-mode link inventory**, but this package does not establish a count of bus stops or a larger admissible transport subset. Each timetable link has a displayed route label, a separate `line` query value, a `node` and an `inprague` flag; the captured link itself does not label the mode. For example, Ametystová has `line=176` and displayed route `245`. Neither the internal URL number nor the number of links is a frequency or day-service measure. The records also contain temporary and disruption timetable notices with their source titles. An independently documented route-to-mode mapping appropriate to the snapshot, timetable validity and the intended counting unit must be resolved before a bus count can be selected.

Across all 21 archived responses, the extractor records 7,326 link occurrences and 1,287 distinct `node` values across **all modes**, with all parsed links marked `inprague=1`. The same stop-list name appears with more than one node zero times; 58 nodes appear with more than one stop-list name. The latter include node 1040, Anděl and Na Knížecí. These are observations about the parsed response, not evidence that a node is a single physical station. Exact link records occur in more than one response for 1,238 distinct records, comparing name, node, query name, displayed route, URL and flags; response pairs S/Š and Z/Ž are byte-identical. The complete per-link inventory keeps every response occurrence and locator; it deliberately does not deduplicate by name or proximity.

Reproduce with `python research/2026-a/data/current_prague_bus_node_candidate/inventory.py` (Python and Beautiful Soup 4). `receipt.json` records all 21 raw hashes and confirms their match to the pre-existing V127 manifest; `all_link_occurrences.csv` points to raw response files and timetable URLs; `name_node_conflicts.json` records observed name/node relationships. No network request or change to the original CSV, model, existing result, or manuscript was made. The capture is from 2026-11-09; the population previously used for Prague is 2025, so any eventual combination would be mixed-year. No candidate count, density, score or admission decision is produced here.
