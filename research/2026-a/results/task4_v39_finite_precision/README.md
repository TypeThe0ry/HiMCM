# Phoenix：有限精度下，最少补数从4项增至5项

当前V38真实输入保持不变：Singapore仍为最坏遗憾规则首选，Phoenix第24，可能冠军25城。新诊断把“最少采集几项”与采集后剩余区间宽度一起计算，避免把精确下端点结果的4项方案误当成实际采集承诺。

| 剩余原区间比例ρ | 最少不同指标数 | 最少方案数 |
| ---: | ---: | ---: |
| 0、1%、2.5% | 4 | 25 |
| 5%、10%、20% | 5 | 21 |
| 50%、100% | 无可行方案 | 0 |

连续辅助权重范围为α∈[0.05,0.20]。Phoenix有7个尚未知的指标，均保留[0,1]。在50%情景，即使全部7项的效用都落在[0,0.5]，仍存在允许偏好使Phoenix保持冠军可能。这里的百分比表示效用区间的相对宽度，不是原始分钟数、师生比的误差百分比或置信水平。

## 如何解释有限精度证书

对采集集合B、剩余比例ρ，把Phoenix的假想上界设为

$$h'_j(B,\rho)=h_j-(1-\rho)(h_j-l_j)\mathbf{1}\{j\in B\}.$$

新诊断枚举子集，求

$$m(\rho)=\min_B\{|B|:\ \forall\alpha\in[.05,.20],\ S_{Phoenix}(h';\alpha)<\max_{k\ne Phoenix}S_k(l_k;\alpha)\}.$$

不存在这样的集合时返回空值。评分对效用单调，因此只需检查候选上界及其他城市下界。连续权重判别沿用已有二次多项式根分区算法，数值容差1e-12；没有用权重网格替代全范围判别。对每个大小穷举全部子集，在首个有证书的大小停止，保存所有并列最少方案。

这要求采集后区间同时**位于不利端且足够窄**。相同宽度若位于有利端[h−ρ(h−l),h]，上界不变，Phoenix仍可能夺冠。因此数据质量提升本身不保证排除，也不能把这个表解释为预计采集收益或调查成本。原有V31/V36收缩门槛已支持区间解释；本轮新增的是给定有限区间宽度时的最少指标数与方案对照。

## 当前模型及验证

主评分保持

$$S_i=100\frac{\sqrt{\sum_jw_ju_{ij}^2}}{\sqrt{\sum_jw_ju_{ij}^2}+\sqrt{\sum_jw_j(1-u_{ij})^2}},\quad L_i=S(l_i),\quad U_i=S(h_i).$$

$$R_i=\max(0,\max_{k\ne i}U_k-L_i),\qquad\mathcal C=\{i:U_i\ge\max_{k\ne i}L_k\}.$$

固定权重为八主指标各0.1125、两辅助各0.05；推荐最小R。教育及通学效用保持V38定义，没有把采集情景写回主模型。

验证包括：独立agent重算所有8个精度情景；ρ=0复现旧算法4项/25方案；随ρ增大最少项数不下降；ρ=1不改变证据；并列不能排除、已严格劣于对手无需测量、非法ρ被拒绝；输入数组不变；25城得分、排名和遗憾逐项复现V38。完整[结果表](minimum_measurements.csv)、[并列方案](minimal_bundles.csv)、[实际排名](ranks.csv)、[摘要](summary.json)。
